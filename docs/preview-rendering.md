## Reviewed idle bridge

Repeated `AfterFX.exe -r` calls remained unreliable despite deferred acknowledgements and spacing. The transport now launches a trusted `idle_bridge.jsx` bootstrap once, then dispatches through AE's `app.scheduleTask` idle queue. Python publishes only a 32-character generated job UUID to `workspace/bridge/inbox.txt`. The listener computes the exact `workspace/jobs/<UUID>/operation.jsx` path; no inbox code or arbitrary paths are accepted. Operation files are generated only from reviewed templates and escaped data. No generic JSX/shell tool or remote listener is exposed.

The listener writes a heartbeat/instance ID, processes one job, and waits for its deferred result before accepting another. Python retains its Windows-session mutex, acknowledgement validation, cancellation-before-mutation guard and 60-second timeout quarantine. A fresh heartbeat avoids all subsequent CLI launches. `astra-studio bridge-start` performs a non-mutating startup/readiness check. If the initial bootstrap has no acknowledgement, retain `bridge/startup-pending.json` and do not relaunch automatically. `studio_status.bridge_runtime.bootstrap_script` gives the generated file for manual **File > Scripts > Run Script File** execution. That bootstrap does not edit projects. A known stale bridge also requires review/manual restart, not a blind second launcher. Closing AE stops its idle tasks; inspect session state before restarting. Use one workspace per session and keep operation scripts trusted/local.

The old timed-out per-command job is not automatically replayed or cleared by starting the listener. Its pending record/cancellation marker require separate audited review. Never overwrite an occupied inbox or clear an active-job marker just to continue.

## Effects and masks

`effect_apply(request)` takes the normal project/composition/layer UUIDs and either `effect="fill"` with `params.color=[r,g,b]` in 0–1, or `effect="gaussian_blur"` with `amount` 0–100 (default 4) and `repeat_edges` (default true). Uses match names `ADBE Fill` and `ADBE Gaussian Blur 2`, not localized labels. Appends a new named effect, never changes prior effects. The new item UUID appears in its name and result `data.item_id`.

`mask_create(request)` takes target UUIDs, `shape` rectangle/ellipse, `bounds=[left,top,width,height]` in **layer coordinates**, optional `mode` add/subtract, `feather` 0–500 px, `opacity` 0–100, `inverted` boolean. Bounds must have positive dimensions up to 20000 and coordinates within ±100000. Generates a closed four-vertex Shape; ellipses use cubic tangents. Adds a static editable mask without replacing earlier masks. User animation of masks is not implemented here.

Both require a clean active verified 2D/unlocked target, snapshot the prior AEP, save/reopen a unique version, compare appended item values and all other inspected state, and only then advance the root manifest. Inspector now includes mask geometry and selected effect parameters. Other effects are summarized by name/match name/enabled/count; this is not exhaustive third-party plugin serialization or rendered-pixel equivalence.

## Preview request and queue

`preview_render(request)` takes project/composition UUIDs, `start_time` (default 0), `duration` 0.1–15 s (default 3), `max_width` 64–1920 (default 1280). Rounds interval boundaries to composition frames. Source is limited to 4K/900 frames, with free-space estimation for worst-case PNG output. Output dimensions remain even and preserve aspect ratio approximately; no upscale. Current previews are **silent H.264/yuv420p MP4**.

Returns `job_id` and `queued` (or `busy` if four outstanding slots are occupied). Poll `job_status(operation_id=<job_id>)`; the host must remain alive for its single preview worker. Jobs journal queued/running/stage/result, owner/process IDs, commands, logs and artifacts. They are not automatically resumed/replayed after host interruption; a stale queued/running journal is not proof that a worker remains alive. Queued source hashes are rechecked before execution.

Preparation copies the saved AEP, safely closes only a clean allowed interactive project, opens the disposable copy, replaces **that copy's queue** with exactly one selected composition/interval, applies an installed lossless image output module and saves it. A `finally` block restores the prior saved interactive project. `ASTRA_PNG_TEMPLATE` configures an operator-installed PNG template name, default `PNG Sequence`. If that default is absent, the backend selects the known `TIFF Sequence with Alpha` preset when actually listed; that is the tested local fallback. Other missing templates fail explicitly with available names. No output template code or renderer arguments come from prompt input. Missing media/plugins/modals may still prevent preparation.

The separate adjacent `aerender.exe` renders queue index 1 of that private AEP without `-reuse`. A native-render pending marker is created exclusively before launch and records owner/renderer PIDs; it also prevents another process from starting a competing renderer in this workspace. Confirmed process exit clears it; timeout/host interruption retains it for review. Original AEP hashes are rechecked. PNG/TIFF frames must be nonempty, consecutively numbered, consistently formatted and have the exact expected count. FFmpeg encodes them to a unique MP4; ffprobe must confirm H.264, yuv420p, dimensions, FPS, duration and decoded frame count. FFmpeg then decodes the entire MP4 with error escalation. Three PNG samples are extracted. Only afterward are the job-owned validated temporary sequence images removed; retain render copy, MP4, samples and logs. Source/parent AEPs and original queues are never saved over.

`job_cancel(operation_id)` requests cancellation for preview jobs only. Queued jobs stop before dispatch. During an active native render, the request prevents subsequent stages after the renderer exits; it does not kill interactive AE or falsely report immediate completion. Native render timeout (300 s) leaves its isolated files and `preview-pending.json`, blocks further previews and requires manual review; the native process may still be active. Encoder/probe stages have bounded timeouts and may terminate only their own helper processes. No universal process-tree cancellation is claimed.

CLI: `effect-apply`, `mask-create`, `preview-render` with `--request '<JSON>'`; `job-cancel --job-id <id>`; poll with `job-status --job-id <id>`. The CLI prints queued state, but Python waits for its preview worker when the process exits; MCP is the intended persistent async host.
